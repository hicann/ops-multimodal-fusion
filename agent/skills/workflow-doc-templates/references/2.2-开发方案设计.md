## 2. 代码架构

本仓算子为「一个 PyTorch 算子 = 一个单文件 AscendC `.asc` kernel」，`.asc` 内联 5 段结构：

1. **Schema**：`TORCH_LIBRARY_FRAGMENT(EXTENSION_MODULE_NAME, m)` 中 `m.def("{op}(...) -> ...")` 注册算子签名。
2. **Meta**：`{op}_meta(...)` 推断输出 shape/dtype（`torch::empty_like` 等），并 `TORCH_LIBRARY_IMPL(EXTENSION_MODULE_NAME, Meta, m)` 注册。
3. **Tiling**：host 侧 `calc_tiling_params(int64_t totalLength)`，用 `platform_ascendc::PlatformAscendCManager::GetInstance()` 取 UB（`GetCoreMemSize`）与核数（`GetCoreNumAiv`），返回 scalar（numBlocks/blockLength/tileSize）。
4. **Kernel**：`__global__ __aicore__ __vector__ {op}_kernel<T>(...)`，内部 `AscendC::TPipe pipe` / `TQue<VECIN|VECOUT>` / `InitBuffer` / `SetGlobalBuffer`（带 `blockLength*GetBlockIdx()` 多核偏移）/ `DataCopyPad` 搬入 + 计算 + `DataCopyPad` 搬出。
5. **NPU Dispatch**：`{op}_npu(...)`：`OptionalDeviceGuard` → `getCurrentNPUStream` → `calc_tiling_params` → `data_ptr()`→`GM_ADDR` → `AT_DISPATCH_SWITCH` 按 `scalar_type()` 分派 `<<<numBlocks, nullptr, stream>>>` → `OpCommand::RunOpApi`，并 `TORCH_LIBRARY_IMPL(EXTENSION_MODULE_NAME, PrivateUse1, m)` 注册。

| Kernel 组织 | 关键特征 | 适用场景 |
|------------|---------|---------|
| 函数式单 kernel | `__global__` 函数直接实现，TPipe/TQue 内联 | 简单 elementwise（add / abs） |
| class 化 kernel | `Kernel{Op}<T>` 封装 Init/Process，薄 `__global__` launcher | 需状态复用的 normalization（layer_norm） |
| 多头文件融合 | `.asc` 仅 host/注册薄层，kernel/tiling 拆到同目录 `.h`，`<<<>>>` 传 tiling struct | 复杂融合算子（swi_glu） |

## 3. 数据流与 Buffer 规划

### 3.1 Host 侧数据流

```
参数校验(TORCH_CHECK) → meta 推断输出 shape/dtype → OptionalDeviceGuard →
getCurrentNPUStream → calc_tiling_params（platform_ascendc 取 UB/核数）→
data_ptr() 转 GM_ADDR → AT_DISPATCH_SWITCH 分派 scalar_t →
{op}_kernel<<<numBlocks, nullptr, stream>>> → OpCommand::RunOpApi 异步 launch
```

### 3.2 Kernel 侧数据流

```
接收 GM_ADDR + tiling scalar → SetGlobalBuffer(blockLength*GetBlockIdx() 多核偏移) →
按 tileSize 分 tile 循环 {
    DataCopyPad 搬入 UB(VECIN) → 矢量计算(如 AscendC::Add / Abs) →
    EnQue(VECOUT) → DataCopyPad 搬出 GM
} → 尾块(tail tile)处理
```

## 4. Tiling 策略

### 4.1 多核切分

按元素总数与核数（`GetCoreNumAiv`）切分：`numBlocks = min(coreNum, ceil(totalLength / MIN_ELEMS_PER_CORE))`，每核处理 `blockLength = ceil(totalLength / numBlocks)` 个元素，`SetGlobalBuffer` 中以 `blockLength * GetBlockIdx()` 做多核地址偏移。

### 4.2 Tiling 参数

```cpp
// host 侧返回 scalar tiling（无 TilingData 结构体）
std::tuple<int64_t, int64_t, int64_t> calc_tiling_params(int64_t totalLength);
// 返回 (numBlocks, blockLength, tileSize)
//   numBlocks  : 使用的 AI Core 数
//   blockLength: 每核处理的元素数
//   tileSize   : 单次搬运 tile 字节数 = ubSize / PIPELINE_DEPTH / BUFFER_NUM
```

| 项目 | 内容 |
|------|------|
| 切分维度 | 按元素总数 / 核数（platform_ascendc） |
| 每核数据量 | blockLength = ceil(totalLength / numBlocks) |
| Tiling 参数 | numBlocks / blockLength / tileSize |

## 7. Host 侧设计

### 7.1 函数拆分

```cpp
// meta：shape/dtype 推断，无计算
torch::Tensor {op}_meta(const torch::Tensor &x, ...);

// npu dispatch：设备守卫 + tiling + kernel launch
torch::Tensor {op}_npu(const torch::Tensor &x, ...) {
    const c10::OptionalDeviceGuard guard(x.device());
    auto z = {op}_meta(x, ...);
    if (x.numel() == 0) return z;                 // 边界快速返回
    TORCH_CHECK(/* 参数约束 */, "...");            // 参数校验
    auto stream = c10_npu::getCurrentNPUStream().stream(false);
    // ... calc_tiling_params / data_ptr() → GM_ADDR ...
    auto acl_call = [=]() -> int { AT_DISPATCH_SWITCH(/* ... */); return 0; };
    at_npu::native::OpCommand::RunOpApi("{Op}", acl_call);
    return z;
}
```

### 7.2 参数校验与错误处理

- 参数校验统一用 `TORCH_CHECK(cond, "msg")`（shape 一致性、dtype 支持、device 等），失败即抛异常，与测试侧 `pytest.raises` 对齐。
- Meta 与 npu dispatch 复用同一 `{op}_meta` 函数，保证 shape/dtype 推断一致。
- 无独立返回码/日志层，错误全部经 `TORCH_CHECK` 异常传播。
